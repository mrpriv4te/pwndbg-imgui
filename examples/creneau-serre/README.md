# Créneau serré

> **404CTF 2026** · category **Exploitation de Binaires**

An example challenge used to try out **pwndbg-imgui**, with a ready-to-fill pwntools
[`exploit.py`](exploit.py) (generated by `pwndbg-imgui --exploit`).

## Files

| File | Description |
|---|---|
| [`chall`](chall) | the challenge binary |
| [`libc.so.6`](libc.so.6) | the libc it was linked against |
| [`ld-linux-x86-64.so.2`](ld-linux-x86-64.so.2) | the matching loader |
| [`exploit.py`](exploit.py) | pwntools harness (payload not implemented — a scaffold) |

## Protections

```
Arch:     amd64-64-little
RELRO:    Partial RELRO
Stack:    No canary found
NX:       NX enabled
PIE:      No PIE (0x3fe000)
```

No PIE and no stack canary, so a stack overflow leads straight to control of the saved
return address.

## The binary

`main` (the only symbol) prints a few French prompts and, three times in a row, `read()`s
input into a **32-byte** stack buffer with **growing** sizes — `0x20`, then `0x28`, then
`0x30` — echoing the buffer back each time (*« Voici ta position »*). Each round overflows
a little further than the last: the "tight parking slot" of the title.

## Usage

```bash
./exploit.py              # run locally
./exploit.py -d           # debug: gdb in a new terminal
./exploit.py -d ui        # debug: the pwndbg-imgui GUI
./exploit.py -r --host HOST --port PORT   # remote
```

With `-d ui`, pwntools launches the program under gdbserver and uses **pwndbg-imgui** as the
debugger — so you drive the program from this script while inspecting it in the GUI. Set a
breakpoint by uncommenting a line in `GDB_COMMANDS` (e.g. `b *main`).

> The `exploit.py` here is the generated scaffold: argument parsing, context setup, the
> `start()` launcher and the debug integration are done — the payload itself is left as an
> exercise (see the commented block under *Exploit*).
